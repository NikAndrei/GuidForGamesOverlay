# Game Help для ПК — проектная записка

Аналог «Справки по игре» (Game Help) с PS5 для игр в Steam: контекстные подсказки по текущему прогрессу игрока, вызываемые поверх игры с клавиатуры или контроллера.

## Принятые решения

- **Универсальная система**: ядро и UI пишутся один раз, под каждую игру добавляются только адаптер сейва и файл подсказок.
- **Источник контекста — файлы сохранений.** Достижения Steam не подходят: они слишком грубые и не отражают текущий момент прохождения.
- **Показ — внедрение в рендер игры (основной путь).** Запасной вариант — прозрачное окно поверх игры.
- **Управление с контроллера — обязательно.**
- Встроиться в оверлей Steam (Shift+Tab) официально нельзя. Отложенная идея: писать подсказки в «Заметки» Steam (файлы в `userdata/<id>/…`). Формат и возможность записи извне не проверены.

## Архитектура

```
[Папка сейвов] → Наблюдатель → Адаптер игры → Общая модель состояния
                                                     ↓
                                        Движок правил + База подсказок
                                                     ↓
                                   Модель UI (что показать сейчас)
                                      ↓                       ↓
                         Рендер-оверлей (основной)   Прозрачное окно (запасной)
                                      ↑                       ↑
                                   Ввод: клавиатура + контроллер
```

1. **Наблюдатель за сейвами.** Следит за папкой сохранений и срабатывает при изменении файла. Нужен debounce, потому что игра часто пишет сейв в несколько приёмов.
2. **Адаптер игры (плагин).** Определение игры (по exe или Steam AppID), путь к сейвам, расшифровка и распаковка, разбор данных. На выходе — общая модель состояния.
3. **Общая модель состояния**, пример:
   ```json
   { "game": "dd2", "quests": [{"id": "...", "stage": 3}], "flags": ["..."], "location": "...", "inventory": ["..."] }
   ```
4. **База подсказок.** Данные в файлах (YAML или JSON) с правилами: условие по состоянию → подсказка. У каждой подсказки три уровня: намёк → подробнее → полный спойлер. Можно добавить скриншоты и видео.
5. **UI.** Список «актуально сейчас», карточка подсказки, раскрытие уровней по одному.

## Рендер-оверлей (основной путь)

- **Вариант А — аддон для ReShade** (рекомендуется для старта). ReShade уже умеет встраиваться в DX9/10/11/12, Vulkan и OpenGL, а через API аддонов можно рисовать своё окно на ImGui. Это избавляет от собственных хуков под каждый графический API.
- **Вариант Б — свои хуки.** MinHook или kiero на `IDXGISwapChain::Present` и `ResizeBuffers` (DX11/12), отрисовка через Dear ImGui. Для Vulkan — явный или неявный Vulkan layer: это официальный механизм, его не нужно взламывать.
- Оверлей рисует только UI. Логику (сейвы, правила) держать в отдельном процессе-сервисе и общаться через named pipe или локальный сокет. Так игра не упадёт из-за ошибки в разборе сейва, а один сервис обслуживает оба способа показа.
- **Риски:** античит (EAC, BattlEye и подобные) может посчитать внедрение читом. Нужны белый список игр без античита и сетевого режима, а также блок-лист известных античитов. Ещё возможны конфликты с другими оверлеями (Steam, Discord, RivaTuner), поэтому нужно тестировать цепочку хуков.

## Прозрачное окно (запасной путь)

- Окно поверх остальных, без рамки, клики проходят насквозь, пока окно не активно. Варианты: Tauri, Electron или нативное окно с тем же ImGui.
- Работает только в оконном режиме без рамки, поверх эксклюзивного полноэкранного не отображается.
- Использует ту же модель UI из сервиса, что и рендер-оверлей.

## Контроллер

- Опрос через SDL3 (SDL_Gamepad): поддерживает Xbox, DualShock/DualSense и Switch Pro. Если нужен только Xbox-формат, хватит XInput.
- **Вызов оверлея** — комбинация, которую игры почти не используют, например удержание View/Share + R3 около 0,5 с. Комбинацию можно переназначить. Кнопку Guide/PS обычно перехватывает Steam, на неё не рассчитывать.
- **Пока оверлей открыт**, ввод не должен уходить в игру. В рендер-оверлее можно перехватывать или подавлять ввод в хуке (у ReShade это проще). Если подавить не получается, можно поставить игру на паузу или предупредить пользователя.
- **Steam Input** может переназначать контроллер и подменять его виртуальным. Это нужно проверить на играх, где Steam Input включён.
- Навигация в UI: крестовина или стик для перемещения, A/✕ — открыть или раскрыть следующий уровень, B/○ — назад, LB/RB — переключение вкладок.

## План MVP

1. Сервис: наблюдатель + интерфейс адаптера + движок правил + отладочная веб-страница состояния.
2. Пилотный адаптер для одной игры с разобранным форматом сейва. Кандидат — DD2, если формат его сейвов поддаётся разбору (проверить наработки сообщества).
3. Аддон ReShade с ImGui-окном: подключение к сервису, показ подсказок.
4. Ввод с контроллера через SDL3: комбинация вызова и навигация.
5. Запасной путь: прозрачное окно на той же модели UI.
6. Позже: проверка трюка с «Заметками» Steam, второй адаптер для проверки универсальности.

## Открытые вопросы

- Пилотная игра и формат её сейва.
- ReShade-аддон или свои хуки в долгосрочной перспективе.
- Язык сервиса (C++ или Rust рядом с оверлеем; C# или Python ради удобства адаптеров).
- Как связать это с уже существующей наработкой в репозитории.
