# GuidForGamesOverlay — план

Проектная записка: [`design.md`](design.md). Здесь — что делаем по шагам и как это связано с GuidForGames.

## Что уже есть в GuidForGames (переиспользуем)

| Что | Где в GuidForGames | Как используем здесь |
|---|---|---|
| Подсказки с лестницей из трёх ступеней (`hints[]`), RU+EN названия, `availableFrom` (ступень прогресса) | `data/<game>/entries/*.json`, пакеты в `NikAndrei/GuidForGames-packs` | Готовая база подсказок. Здесь добавляются только правила «состояние → какие записи актуальны сейчас» |
| Шкала прогресса игры (`progress[]`) и сопоставление ID квестов из сейва | `data/<game>/game.json`, `data/dragons-dogma-2/save-map.json` | Общая модель состояния, поля `progress` и `quests` |
| Расшифровка и разбор сейва DD2 («Mandarin», ключ из SteamID64, RSZ) | `tools/dd2-save` (Rust, поверх ree-save-editor), `docs/save-reading.md` | Пилотный адаптер DD2: сервис вызывает утилиту на копии сейва. Позже можно подключить её как библиотеку (обе на Rust) |
| Мод-мост REFramework для DD2 и RE4: позиция, отслеживаемый квест, журнал, сундуки, глава и т.д. | `mods/dd2/guidforgames.lua`, `mods/re4/guidforgames.lua` → `reframework/data/guidforgames_*.json` | Второй источник состояния: точнее и быстрее сейва (обновляется раз в 2 с). Адаптер читает эти JSON |

## Принятые решения (03.11.2026)

- **Сервис — на Rust** (`service/`, крейт `gfg-service`). Рядом с `dd2-save` и ree-save-editor.
- **Показ — аддон ReShade для всех игр**, в том числе для игр на RE Engine. Окно внутри мода REFramework
  не делаем: путь через ReShade одинаков для всех игр, поэтому новые игры подключать проще. Мод-мост остаётся
  источником состояния, а не способом показа. ReShade и REFramework ставятся в одну игру вместе:
  совместимость цепочки хуков нужно проверить на DD2.
- **Связь с оверлеем — TCP на localhost, JSON по строкам** (протокол в `service/README.md`). Работает одинаково
  из аддона на C++ (Winsock) и из прозрачного окна. Named pipe не понадобился.
- **Правила — JSON**, как данные GuidForGames.

## MVP

1. ✅ **Формат и модель.** JSON Schema общей модели состояния (`schemas/state.schema.json`) и правил подсказок
   (`schemas/hints.schema.json`). Пример правил для DD2 (`hints/dd2/`), который ссылается на записи GuidForGames.
2. ✅ **Сервис.** Наблюдатель за папками (с debounce), интерфейс адаптера, движок правил, модель UI
   («актуально сейчас»), TCP-протокол для оверлея и отладочная веб-страница состояния.
3. ✅ **Пилотный адаптер DD2.** Источник 1: сейв `win64_save/*` через `dd2-save`. Источник 2: `guidforgames_live.json`
   и `guidforgames_state.json` из мода-моста, если они есть. Журнал квестов берётся из более свежего источника.
   Проверено на тестовых файлах мода и настоящих записях DD2. **Нужно проверить на ПК** с игрой: мод и сейв.
4. **Показ в рендере (следующий шаг).** Аддон ReShade (C++, `overlay/reshade-addon/`) с ImGui-окном: подключается к сервису, показывает список «актуально сейчас»
   и карточку подсказки, уровни раскрываются по одному.
5. **Контроллер (SDL3).** Вызов окна удержанием View/Share + R3 (~0,5 с), комбинацию можно переназначить.
   Навигация: крестовина/стик, A/✕ — раскрыть, B/○ — назад, LB/RB — вкладки. Пока окно открыто, ввод в игру подавляется.
6. **Запасной путь.** Прозрачное окно (Tauri/Electron/ImGui) на той же модели UI.
7. **Позже.** Проверить, можно ли писать в «Заметки» Steam. Второй адаптер (RE4) для проверки универсальности.

## Открытые вопросы

1. **Steam Input:** проверить, видит ли SDL3 контроллер, когда Steam подменяет его виртуальным.
2. **ReShade + REFramework в DD2:** работают ли вместе (оба встраиваются в DX12).
3. **Кириллица в ImGui аддона:** загрузить свой шрифт с кириллическими глифами.
4. **Определение игры:** сейчас текущая игра — та, чьё состояние обновлялось последним.
   Аддон может сообщать сервису exe игры, в которую он загружен.
5. **Правила для DD2:** в `hints/dd2/` пока три правила для проверки. Нужно покрыть основные и побочные квесты.
